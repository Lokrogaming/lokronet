Warum LokroNet

Signierter Handshake

Ephemerer X25519 pro Peer-Paar, mit Ed25519-Identität signiert. Session-Code out-of-band vergleichen – kein Trust-on-first-Use im Blindflug.

Geteilte History

Der Daemon hält ~/.lokronet/chat-history.json (0600). TUI, CLI und Desktop lesen dieselbe IPC – überall derselbe Stand.

Presence-Beacons

Boot-Beacon an alle Kontakte, danach periodisch. Online-Anzeige aus Beacons, Retry inklusive – offline wird ehrlich als offline gezeigt.

Direct zuerst, Relay als Fallback

UDP-Direct wenn erreichbar, sonst msg-data-Relay über Rendezvous. Der Relay sieht nur Cipher – kein Klartext.

Zwei Dashboards

lokronet dashboard (Terminal-UI mit Chat) für den Alltag, dashboard-web (nur Loopback) für Server-Checks.

Keine Server-DB

Mailbox nur In-Memory (cap 50), keine Persistenz serverseitig. Sync-Prinzip: neueste Timestamps gewinnen.

fluss: app → daemon (localhost + token) → rendezvous/peer

Desktop/TUI/CLI ──IPC──▶ Daemon (History, Sessions, Beacons) ──Signaling──▶ Rendezvous :8787 (Discovery + opake Blobs)
                                                        └────UDP-Direct / msg-data-Relay────▶ Peer (NaCl-box, E2E)

Schnellstart

1–2 · registrieren & beacon

lokronet setup --rendezvous http://DEIN-SERVER:8787
lokronet beacon

3–4 · handshake & chat

lokronet chat open --id 123456789012
lokronet chat send --id 123456789012 --text "hallo"

5 · UI öffnen

lokronet dashboard   # TUI mit Chat
# oder: desktop/LokroNet.Desktop – dotnet run

6 · status prüfen

lokronet presence
lokronet chat sessions   # Code vergleichen!

Sicherheit

  • ID ≠ Secret. 12 Ziffern sind nur Adresse; Auth via Ed25519 + Fingerprint/Session-Code.
  • E2E-Pflicht. XSalsa20-Poly1305, Nonce aus (Seq + Rolle), Replay-Fenster, kein Klartext in Logs.
  • Lokal gehärtet. IPC nur Loopback + Token, Dateien 0600/0700, Daemon least-privilege.
  • Ehrlich statt magisch. NAT ohne Port-Forward → Relay-Hinweis statt stillem Fail; offline → offline.
